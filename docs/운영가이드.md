# 마케팅 대시보드 운영 가이드

모두의연구소 K-Digital Training 모집 현황을 과정·기수별로 보는 Streamlit 대시보드입니다.
이 문서는 실행 방법, 설정 위치, 지표 정의, 현재 데이터로 제공하지 못하는 항목을 정리합니다.

## 1. 실행과 테스트

```bash
pip install -r requirements.txt
streamlit run app.py            # http://localhost:8501
python -m unittest discover -s tests -t .   # 집계·분류·액션 로그 단위 테스트
```

- 인증은 `.streamlit/secrets.toml`의 `[gcp_service_account]` 또는 환경변수 `GCP_SERVICE_ACCOUNT_JSON`을 사용합니다. 파일은 Git에 올리지 않습니다.
- 서비스 계정은 각 2.2 지원자 스프레드시트에 **뷰어** 이상으로 공유되어 있어야 합니다.
- 광고 데이터는 BigQuery `Modulabs_internal_DB.dash_daily_inflow`에서 읽습니다. 적재는 `scripts/export_inflow_to_bq.py`가 담당합니다.

## 2. 화면 구성

| 탭 | 질문 | 주요 내용 |
|---|---|---|
| 📈 종합 현황 | 어떤 과정이 목표에 못 미치는가? | 모집 목표·필요 속도, 기수 누적 전형 현황, 예산·CPA, 매체별 전형, 사유, 메타 소재, GA 퍼널, 전체 기수 비교 |
| 📅 주차별 현황 | 어느 매체가 효율적이고, 전주 대비 어떻게 변했나? | 주 단위 매체 효율과 전주 대비, 선택 주 지원자의 현재 전형 결과, 사유, 근거 기반 인사이트, 최근 8주 |
| 📆 일자별 현황 | 최근 추이와 급변, 데이터 이상은? | 일별 광고비·지원·CPA, 7일 CPA(합계 기준), 누락 경로, 급감 매체, 데이터 상태, 액션 로그 전후 비교 |
| ⚙️ 설정·지표 정의 | 숫자가 무엇을 뜻하나? | 지표 정의, 분류 규칙, 기준값, 데이터 연결 상태, 액션 로그 입력 가이드 |

사이드바에서 과정을 고르면 **그 과정의 모집 중인 기수**(`RECRUITING_COHORTS`)가 기본 선택됩니다. 모집 중인 기수가 없는 과정은 가장 최근 기수가 기본입니다. 종료된 기수도 모두 선택할 수 있으며, 모집 목표는 설정이 없는 기수에서는 표시하지 않습니다.
사이드바의 **조회 기간**은 일자별 현황과 표의 기간 필터에 적용됩니다. **매체**는 지원 매체 표에 적용되며, 광고 전용 블록(오가닉·타게팅게이츠·기타 등)은 항상 표시합니다.
사이드바의 **데이터 새로고침**을 누르면 캐시를 비웁니다. 데이터 로드 실패 결과는 캐시되지 않으므로 다시 누르면 재시도됩니다.

## 3. 설정 위치 (`src/config.py`)

| 항목 | 변수 | 비고 |
|---|---|---|
| 목표·모집 기간·예산 | `COHORT_SETTINGS`, `DEFAULT_COHORT_SETTING` | 키는 `(과정ID, 기수)`. 값이 없으면 '미설정'으로 표시하고 계산하지 않음 |
| 주 시작 요일 | `WEEK_START_WEEKDAY` | 0 = 월요일 |
| 광고비 부가세·수수료 | `AD_COST_INCLUDES_VAT_AND_FEE` | 표시 문구에만 쓰임. 실제 값은 대행사 raw 기준 |
| 인사이트·경고 기준 | `MIN_COST_FOR_CPA`, `MIN_SAMPLE_FOR_INSIGHT`, `CPA_WORSE_RATIO` 등 | **초기값은 가정**이며 운영하며 조정 |
| 유입 채널 → 매체 그룹 | `CHANNEL_GROUP_MAP` | 목록에 없는 채널은 '미분류' |
| 유료 매체 | `PAID_CHANNEL_GROUPS`, `MATCHED_AD_GROUPS` | `MATCHED_AD_GROUPS`만 광고 블록과 맞춰 유료 매체 CPA 계산 |
| 액션 로그 시트 | `ACTION_LOG_SHEET_ID`, `ACTION_LOG_SHEET_NAME` | 아래 4절 |

예시 (목표 설정):

```python
COHORT_SETTINGS = {
    ("ai_agent", 2): {"target_kind": "지원", "target_count": 300,
                      "recruit_start": "2026-05-25", "recruit_end": "2026-08-20", "budget": 50_000_000},
}
```

`target_kind`는 목표가 무엇인지 명시합니다(`지원` / `최종합격` / `등록`). 최종합격·등록 목표에서는 필요한 지원자 수를 임의로 계산하지 않습니다.

`recruit_end`(모집 마감일)를 비워 두면 과정·기수 스프레드시트의 **2.1 일자별 유입현황 시트 최하단 일자**를 마감일로 씁니다. 값을 직접 입력하면 입력값이 우선합니다.

## 4. 마케팅 액션 로그 설정

액션 로그는 Google 스프레드시트 탭에 저장합니다. 대시보드는 읽기만 하므로 새 쓰기 권한이 필요하지 않습니다.

1. 기존 대시보드용 스프레드시트 중 한 곳(또는 팀 공용 시트)에 탭 **`마케팅 액션 로그`** 를 만듭니다.
2. 첫 행에 다음 헤더를 입력합니다.
   `변경일 | 과정ID | 기수 | 매체 | 캠페인·소재 | 변경유형 | 변경내용 | 변경이유 | 담당자 | 추후 확인 지표 | 확인 예정일`
3. 서비스 계정 이메일을 해당 스프레드시트에 **뷰어** 이상으로 공유합니다.
4. 스프레드시트 ID(URL의 `/d/`와 `/edit` 사이)를 `src/config.py`의 `ACTION_LOG_SHEET_ID`에 입력합니다.
5. 입력 규칙
   - 변경일은 `YYYY-MM-DD`. 형식이 틀린 행은 무시됩니다.
   - 과정ID를 비우면 모든 과정, 기수를 비우면 과정 전체에 적용됩니다.
   - 변경유형 예시: 예산 조정, 소재 교체, 타깃 변경, 랜딩페이지 수정, 지원 절차·자격 안내 수정.
   - 입력 권한은 시트 공유 설정으로 관리합니다(예: 마케팅 팀은 편집자, 나머지는 뷰어).

액션은 일자별 차트에 점선으로 표시되며, 액션 전후 7일의 광고비·지원·CPA를 함께 보여 줍니다.
이 비교는 단순 전후 비교이므로 인과적 효과로 해석하지 않습니다.

## 5. 지표 정의

| 지표 | 정의 | 분모·기준 |
|---|---|---|
| 지원 | 2.2 시트 신청자 행 수 (지원서 1건 = 1행) | 타 과정 이관 건 제외. **중복 제거 안 함** (동일인 식별 키가 시트에 없음) |
| 누적 통과 | 해당 단계 또는 이후 단계 기록이 있으면 통과. 단, 서류 열이 X로 명시된 건은 뒤 단계 기록이 있어도 서류 통과로 보지 않음 | 서류 통과율 분모 = 서류 판정 인원 / 인터뷰 통과율 분모 = 인터뷰 O·X 또는 최종 이상 |
| 현재 단계 | 지금 머무는 단계 (아래 우선순위) | 확정 단계 = 등록·탈락·불참·포기·이관 |
| 지원 CPA (유료 매체) | 메타·구글 DA·구글 SA·네이버 SA·카카오 DA 광고비 ÷ 해당 매체 지원 | 지원은 모집 기간 밖 포함(사전 신청·광고 데이터 밖 지원 포함). 광고비만 광고 데이터 기간 안으로 집계 |
| 지원 CPA (전체 모집 비용) | 전체 광고비 ÷ 전체 지원 (자연 유입 포함) | 유료 매체 CPA와 **다른 지표**로 표기 |
| 최종 합격 CPA | 광고비 ÷ 최종 합격(누적) | 전형 진행 중이면 잠정값 |
| 7일 CPA | 최근 7일 광고비 합 ÷ 최근 7일 지원 합 | 일별 CPA의 평균 아님 |
| CTR / CPC / CPM | 클릭÷노출 / 광고비÷클릭 / 광고비÷노출×1,000 | 매체 집계 단위(회) |

현재 단계 우선순위: 이관 > 서류 탈락 > 인터뷰 탈락 > 인터뷰 불참 > 수강포기(인터뷰 합격 이후만) > 등록 > 최종 합격 > 인터뷰 > 서류.
탈락 기록은 포기 표기보다 먼저 일어나므로, 서류 탈락 뒤 `수강포기` 표기가 있어도 '서류 불합격'으로 집계합니다.

탈락·포기 사유 표의 구분은 세 가지입니다.
- **서류**: 서류 불합격
- **인터뷰**: 인터뷰 불합격과 인터뷰 불참 (불참은 사유 열에 `불참`으로 표기하고, 시트 사유 문구가 있으면 `불참 (문구)`로 함께 씁니다)
- **수강 포기**: 인터뷰 합격 이후 포기

사유 문구는 시트에 적힌 대로 쓰며, 타 과정 이관은 이 표에서 제외합니다.

분모가 0이면 '계산 불가'로 표시하고, 전주 값이 0이면 증감률 대신 '신규 발생'으로 표시합니다.

## 6. 현재 데이터로 제공하지 못하는 항목과 필요한 데이터

| 항목 | 현재 상태 | 필요한 것 |
|---|---|---|
| 광고 소재·캠페인별 광고비·노출·클릭, 소재별 CPA | 2.1·BigQuery는 매체(블록) 단위만 있음 | 광고 플랫폼 소재·캠페인 리포트를 일자·소재 단위로 적재 |
| 지원자별 UTM·캠페인 식별값 연결 | 2.2 시트에 UTM이 없음. 유입 채널은 수동 분류 | 지원서 폼에 UTM·캠페인 ID 숨김 필드 추가 (GA 세션 ID와 결합하면 귀속 가능) |
| 결과 처리일 기준 분석 (6-2 두 번째 기준) | 상태 변경 이력 없음 | 전형 상태 변경 시각을 기록하는 열 또는 이력 탭 |
| 과거 시점 상태 복원 | 불가. 조회 시점 상태만 있음 | 위와 같음 |
| 동일인 중복 제거 | 이름만 있어 동명이인과 구분 불가 | 연락처 해시 등 고유 키 |
| 등록(수강료 결제) 집계 | 일부 기수는 '수강료 결제' 열이 없음 | 해당 열 추가 |
| 목표·모집 기간·예산 | 미입력 (가정값 없음) | 운영팀이 `COHORT_SETTINGS`에 입력 |
| 노출·클릭과 GA 세션 단위 연결 | 단위가 달라 전환율은 GA 단계끼리만 계산 | 매체 클릭 ID 또는 UTM 기반 세션 연결 |
| 전형 통과 예측 시나리오 | 미구현 (데이터·전환율 판단 필요) | 기수별 전형 이력 누적 후 검토 |

## 7. 알려진 한계와 가정

- 2.2 `네이버 브검`(네이버 브랜드검색 광고)은 `네이버 SA`와 분리해 별도 매체 그룹으로 집계합니다. 유료 유입으로 세지만, 2.1에 별도 광고비 블록이 없어 CPA는 계산하지 않습니다.
- **확인 필요(파이프라인):** GA에서 `naver / bsa_pc·bsa_mo`는 시트에 `네이버 브검`으로 기록되지만, `scripts/update_2_1_channels.py`의 `block_of()`는 `naver / cpc`만 `네이버 SA`로 보므로 브검 트래픽이 2.1에서 `오가닉`으로 잡힐 수 있습니다. 이 경우 브검 광고비·지원이 매체 효율에 반영되지 않습니다. 파이프라인 수정 여부는 별도로 결정해야 합니다.
- 지원·서류·인터뷰·최종 합격·등록과 CPA 분모는 모집 기간 밖에 들어온 지원자도 포함합니다. 2.1 광고 데이터가 지원자 데이터보다 짧으면 광고 데이터가 없는 날의 지원도 분모에 들어가므로, 광고비 없는 지원이 CPA를 낮추지 않도록 화면의 광고 기간 표기를 함께 확인하세요.
- 종료된 기수는 광고 데이터가 멈춰 있을 수 있습니다. 일자별 현황의 '데이터 상태'는 이를 오류가 아니라 안내로 표시합니다.
- '수강포기'는 인터뷰 합격 이후에 포기한 사람만 포기로 집계합니다. 그 이전 단계의 표기는 무시합니다. 시트 기록 기준을 운영팀과 확인해야 합니다.
- 인사이트의 CPA 상승은 원인을 단정하지 않습니다. 점검 대상(소재·타깃·랜딩)을 좁히는 용도입니다.
- 탈락·포기 사유는 시트에 적힌 문구 그대로 집계합니다. 임의 분류는 하지 않으며, 같은 구분 안에서 사유별 비율을 보여 줍니다.

## 8. 추적 구조 점검 요약 (3차 7-3)

- **유입 귀속:** GA 이벤트에 `source / medium / campaign`이 있어 블록 단위 귀속은 가능합니다(`scripts/update_2_1_channels.py`의 `block_of`).
- **연결 불가 구간:** 지원서(2.2)와 GA 세션을 잇는 키가 없어 지원자별 매체 귀속은 확인할 수 없습니다. 시트의 '유입 채널'은 담당자가 분류한 값입니다.
- **권장 개선:** (1) 지원서 폼에 UTM과 캠페인 ID를 숨김 필드로 수집, (2) 광고 플랫폼 소재 리포트를 일 단위로 BigQuery에 적재, (3) 전형 상태 변경 시각 기록.
